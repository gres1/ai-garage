# Бриф: AI Garage — десктопное приложение (menubar) для macOS

**Для агента-исполнителя.** Цель: завернуть существующую веб-панель AI Garage в нативное
приложение macOS с иконкой в строке меню (menubar). Веб-часть НЕ переписывать — переиспользовать.

## Что уже есть (не трогать логику)
- Репозиторий: `~/Documents/App/localhost-control/` (npm `ai-garage`, GitHub `gres1/ai-garage`).
- `server.mjs` — Node-сервер без зависимостей, слушает `127.0.0.1:7777`, отдаёт UI + REST API
  (`/api/status`, `/api/start|stop|restart`, `/api/kill-port`, `/api/tunnel-*`, `/api/keepalive`,
  `/api/service-*`, `/api/cat-override`, `/api/can-embed`).
- `public/index.html` — весь UI (vanilla JS, i18n, без сборки).
- `mcp.mjs` — MCP-сервер для агентов.
Сервис управляет процессами через `lsof`/`spawn`/`kill`, туннели через `cloudflared`, keep-alive
супервизит сам сервер.

## Цель десктопа
1. Иконка в menubar (tray) со сводным статусом (сколько сервисов «running», напр. бейдж «10/14»).
2. Клик по иконке → выпадающее окно с панелью (тот же `index.html`).
3. Autostart при логине.
4. Приложение само поднимает локальный сервер (sidecar) — пользователю не нужен терминал.

## Технология: Tauri 2
- Tauri = Rust-обёртка + системный webview (на macOS — WKWebView). Бандл лёгкий (~3–10 МБ против
  ~100 МБ Electron).
- **Node-сервер запускать как sidecar** (Tauri `externalBin`/sidecar): приложение стартует `server.mjs`
  на 127.0.0.1:7777, webview грузит `http://127.0.0.1:7777`. Это переиспользует ВЕСЬ backend без
  переписывания. Альтернатива (если уходить от Node) — переписать API на Rust, но это бОльшая работа;
  на первом этапе — sidecar.
- Tray: `tauri-plugin-positioner` + tray API (есть в Tauri 2). Autostart: `tauri-plugin-autostart`.
  Нотификации (опц.): `tauri-plugin-notification`.

## Шаги
1. `npm create tauri-app@latest` (vanilla, без фронт-фреймворка — у нас готовый HTML).
2. Настроить sidecar: положить Node-бинарь или требовать системный Node; спавнить `server.mjs` при старте,
   глушить при выходе.
3. Tray-иконка + popover-окно (frameless, грузит 127.0.0.1:7777). Бейдж статуса обновлять опросом
   `/api/status` (или из Rust).
4. Autostart-плагин. Подписать (ad-hoc для теста; Developer ID для распространения).
5. Сборка `.app`/`.dmg`.

## Ограничения Tauri vs нативный Swift (важно — ответ на вопрос Az)
- **Функциональных ограничений для НАШЕЙ задачи нет.** Всё, что делает панель (lsof, kill, spawn,
  cloudflared, чтение файлов в ~/.config) — это работа Node-сайдкара/Rust, а не webview. Доступ к
  системе полный (приложение запускается с правами пользователя).
- **Menubar/tray, autostart, нотификации** — всё поддерживается Tauri 2 из коробки (плагины).
- **macOS TCC** (доступ к ~/Documents и т.п.) — те же правила, что и у любого приложения; решается
  подписью + запросом доступа. Это НЕ ограничение Tauri (нативный Swift столкнулся бы с тем же).
- **Где Swift был бы лучше:** только если нужен сложный нативный UI без веба — у нас наоборот, UI уже
  веб, и его переиспользование = главный плюс Tauri. Swift тут добавил бы работу, а не возможности.
- **Кросс-платформенность:** Tauri = один код на macOS + Windows + Linux. Swift = только Apple. Для
  продукта с прицелом на разные ОС Tauri выигрывает. (Мобильные iOS/Android Tauri 2 поддерживает, но
  для menubar-утилиты это не нужно — на телефоне используется веб-доступ через туннель/Pro-реле.)

**Вывод:** Tauri 2 + Node-сидкар подходит полностью; нативный Swift не даёт преимуществ для этой
задачи и теряет кросс-платформенность.

autostart работает, есть `.dmg` для установки.
